## Shared responsibilities
Every member is expected to:
- Attend sprint planning, check-ins and sprint reviews.
- Follow the shared component, route and database contracts.
- Work on a feature branch rather than directly on `main`.
- Commit focused changes with clear messages.
- Open pull requests and review another member's work.
- Test their feature and help resolve integration issues.
- Be able to explain their implementation during the final presentation.

## Ownership boundaries
Feature ownership does not mean a member works in isolation. Coordinate shared files such as `App.jsx`, `db.json`, `package.json`, global styles and shared contexts before editing them. Agree on changes in the team channel and avoid simultaneous conflicting edits.
